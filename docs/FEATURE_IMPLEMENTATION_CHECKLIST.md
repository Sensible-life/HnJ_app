# 기능 구현 체크리스트 (PDF 원안 기준)

`앱개발 메뉴 리스트.pdf`에 있던 기능 목록과, 그걸 바탕으로 우리가 구현하기로 합의한 백로그
(`docs/FEATURE_SCOPE.md` 4장 우선순위 A/B/C)를 기준으로 "무엇이 어떻게 구현됐는지"를 정리한 문서다.
QA 체크리스트(`docs/QA_CHECKLIST.md`, `docs/QA_PRIORITY_BC.md`)와 달리 이 문서는 테스트 항목이 아니라
**기능 구현 현황과 구현 방식 설명**이 목적이다.

표기 기준: `[x]` 완료 · `[~]` 부분 구현(핵심은 되지만 남은 부분 있음) · `[ ]` 미구현(Mock/자리만 있음)

---

## 1. 점검 시작

- [x] **호텔 선택** — 하드코딩된 호텔명 대신 `GET /hotels`로 실제 호텔 목록을 불러와 체크인 화면에서
  선택. 서버가 꺼져 있어도 체크인 자체는 진행되도록 폴백 유지.
- [x] **담당자 선택** — `GET /admin/users`(INSPECTOR 역할만 필터)로 실제 담당자 목록을 불러와 선택.
  로그인 기능이 붙기 전까지의 임시 방식.
- [x] **서비스 구분** — 최초 리뉴얼 / 정기점검 / 긴급출동 / 재점검 4종을 체크인 화면에서 선택,
  점검 세션에 저장돼 리포트 헤더에 라벨로 표시됨.
- [x] **방문일시 자동 기록** — 세션 시작 시각을 로컬에 자동 저장.
- [x] **GPS 체크인** — 체크인 시 위/경도 자동 기록.
- [~] **QR 체크인** — QR 스캔은 되지만, 스캔한 값을 그대로 객실명으로 쓰고 있음. 서버의 실제 객실
  DB와 대조(lookup)하는 로직은 아직 없음.
- [ ] **NFC 체크인** — 버튼/안내 UI만 있고 실제 NFC 태깅은 미구현. Expo Go 환경의 한계로 별도
  개발 빌드(dev client)가 필요해서 이번 스코프에서는 보류.

## 2. ROOM PRO (객실 인스펙션)

- [x] **호텔명/객실번호** — 세션에 저장, 화면·리포트에 표시.
- [x] **객실 유형** — 체크인 때 고른 값을 이어받고, ROOM PRO 화면에서도 칩으로 직접 선택/변경 가능.
  세션에 저장돼 리포트에 반영.
- [x] **청소 담당팀 기록** — A팀/B팀/C팀(서버에서 관리, 관리자 웹에서 팀 추가 가능)을 화면에서
  칩으로 선택. 나중에 "청소팀별 인스펙션 점수" 통계와 자동으로 연결됨.
- [x] **청소 완료시간 기록** — "청소 완료" 토글을 켜면 그 순간의 시각을 자동 저장, 리포트에 표시.
- [x] **분실물 발견 여부/보관 장소** — 발견 여부 토글 + 보관 장소 텍스트 입력, 리포트에 눈에 띄는
  강조 박스(🎒)로 표시.
- [x] **`해당 없음` 상태 추가** — 기존 정상/주의/긴급 3단계에 "해당 없음"을 더해 4단계로 확장
  (예: 욕조가 없는 객실의 "욕조 상태" 항목).
- [x] **항목별 문제 내용 / 조치 내용 입력** — 주의·긴급 항목마다 "무슨 문제인지"와 "현장에서 어떻게
  조치했는지"를 각각 입력해 리포트에 반영.
- [x] **항목별 문제 유형 분류** — 곰팡이/누수/악취 등 유형을 칩으로 선택, 통계의 "유형별 문제 통계"와
  연결.
- [x] **호텔 승인 필요 여부** — 항목별로 토글해서 표시하면, 동기화 시 자동으로 승인 티켓이 생성됨.
- [~] **점검 담당자** — 화면에는 담당자를 선택해서 표시하지만, 실제 로그인 계정과 연결된 건 아직
  아니라서(로그인 기능 자체가 임시 상태) 완전한 구현은 아님.
- [~] **화장실 문제 시 BATH PRO 자동 연결** — 화장실 관련 항목이 주의/긴급이면 BATH PRO로 넘어가는
  버튼이 뜨지만, 자동 판단 기준(어떤 항목이 몇 개 이상일 때)은 room-03 항목 하나로 단순화돼 있음.
- [~] **객실 점검항목 구성** — 현재 15개 항목으로 구현돼 있는데, PDF 원안의 세부 항목과 1:1로
  맞는지는 별도 검토가 필요.

## 3. BATH PRO (화장실 케어)

- [x] **정상/주의/긴급/해당없음** — ROOM PRO와 동일하게 4단계.
- [x] **문제 내용 / 조치 내용** — 항목별 입력, 리포트 반영.
- [x] **호텔 승인 필요 여부** — 항목별 토글, 승인 티켓 생성 조건에 반영.
- [x] **담당자 의견** — 세션 전체에 대한 총평을 하나 입력하면 리포트 헤더와 관리자 웹 타임라인에 노출.
- [x] **짧은 동영상 등록** — "🎥 동영상" 버튼으로 최대 15초 촬영, 사진과 별도로 `동영상`으로 태깅돼
  저장·업로드됨(사진에 입히는 워터마크는 동영상에는 적용하지 않고 원본 그대로 저장).
- [x] **예상 비용 / 재방문 예정일 / 수리 자재** — 입력 필드로 구현, 리포트에 표시.
- [~] **교체/수리 필요 여부** — 별도 토글은 없고, 수리 자재·비용을 입력했는지로 대신 판단하는 방식.

## 4. 사진/영상

- [x] **점검 전/작업 중/작업 후 사진** — Before/During/After 3종으로 구분 저장.
- [x] **짧은 동영상 등록** — 위 BATH PRO 항목과 동일.
- [x] **객실번호/촬영시간 자동 표시** — 서버에서 사진에 자동으로 워터마크(객실명+시각)를 합성.
- [x] **긴급 판정 시 사진 필수** — ROOM PRO에서 긴급으로 표시하면 사진 없이는 넘어갈 수 없게 강제.
- [~] **문제 부위 확대사진** — 별도의 "확대사진" 타입은 없고, 지금은 일반 사진과 같은 방식으로만 처리.
- [~] **사진 위 화살표/원 표시(Quick-Draw)** — 관리자 웹에서 그려볼 수는 있는데, 그린 결과를 저장해서
  나중에 다시 불러오는 기능은 아직 없음(매번 새로 그려야 함).

## 5. 리포트/승인

- [x] **호텔명/객실번호/점검 항목 상태** — HTML/PDF 리포트에 모두 포함.
- [x] **현장 조치내용** — 문제/조치 내용이 리포트에 그대로 노출.
- [x] **호텔 담당자 의견 또는 답변** — 1-Click 승인/재점검 웹페이지에 코멘트 입력란이 있고, 입력한
  내용이 처리 완료 화면에 다시 보임.
- [x] **호텔 확인 버튼(1-Click 승인)** — 문자/알림 링크로 들어가서 버튼 하나로 승인.
- [x] **PDF 저장/공유** — 리포트별로 "공유용 링크+텍스트"를 만들어주는 기능을 추가, 관리자 웹
  객실 타임라인에서 "PDF 공유" 버튼으로 바로 복사할 수 있음.
- [x] **문자(SMS) 알림** — 긴급 항목이 발생하면 기존 카카오 알림톡과 함께 문자도 같이 발송되도록
  추가(현재는 실제 발송이 아니라 발송 로그만 남기는 Mock 상태 — 실제 문자 발송 서비스 계약/API키가
  필요한 부분).
- [~] **점검시간/담당자** — 리포트에 표시는 되는데, 담당자 정보가 아직 실제 로그인 계정 기반이 아님
  (위 ROOM PRO 항목과 같은 이유).
- [~] **예상 비용/재점검 예정일/추가 수리 필요사항** — BATH PRO에서 입력한 값으로 대신 채워지고 있음.
- [ ] **전체 점검점수** — 항목들을 하나의 점수(예: 100점 만점)로 합산하는 계산식이 아직 없음. 어떤
  가중치로 점수를 매길지 기준을 먼저 정해야 하는 부분.

## 6. 관리이력 (관리자 웹 — 객실 타임라인)

- [x] **객실별 과거 점검기록** — 호텔+객실을 선택하면 그동안의 점검 이력이 시간순으로 나열됨.
- [x] **점검 전/후 사진 비교** — 슬라이더로 좌우 비교.
- [x] **날짜별 사진 비교** — 첫/마지막 사진뿐 아니라, 임의의 두 시점 사진을 골라서 비교할 수 있게
  확장(동영상은 비교 슬라이더 대상에서 제외하고 안내 문구로 대체).
- [x] **재발 횟수** — 같은 호텔·같은 객실·같은 항목에서 문제가 2회 이상 반복되면 통계에 자동으로
  잡힘.
- [~] **수리/교체 내역, 다음 점검 예정일, 담당 작업자, 호텔 확인 여부** — 개별 항목으로 화면에
  일부 표시는 되지만, 별도의 "관리이력 전용 데이터"로 정리된 건 아니고 점검 세션 데이터에서
  추론해서 보여주는 수준.

## 7. 통계 (관리자 웹 대시보드)

- [x] **담당자별 점검 실적** — 담당자별 세션 수/불량 건수/긴급 건수/불량률.
- [x] **호텔별 문제 발생 순위** — 불량률 기준으로 순위를 매겨서 배지로 표시.
- [x] **객실별 문제 발생 횟수** — 어떤 객실에서 문제가 많이 나왔는지 집계.
- [x] **반복 문제 객실(재발 횟수)** — 위 "관리이력"과 같은 데이터를 대시보드에서도 보여줌.
- [x] **전월 대비 개선율** — 이번 달과 지난 달의 불량률을 비교한 증감률(데이터가 부족하면 표시 안 함).
- [x] **청소팀별 인스펙션 점수** — 팀별로 담당한 점검의 "정상 비율"을 점수화.
- [x] **화장실 상태 변화 그래프** — 최근 14일간 BATH PRO 점검의 정상/주의/긴급 건수를 막대그래프로
  시각화.
- [x] **월간 총 점검 객실 수, 객실 청소 불량률** — 기존부터 있던 대시보드 지표.
- [~] **곰팡이/누수/악취 등 유형별 통계** — 항목별로 문제 유형을 고를 수는 있지만, 이걸 별도로 모아
  "유형별 통계 카드"로 보여주는 화면은 아직 없음(데이터는 쌓이고 있어서 나중에 추가하기는 쉬움).
- [~] **조치 완료율/미조치 건수/재점검 필요 객실** — 대시보드에 일부 지표로 있지만, 실제 조치
  이력을 관리하는 전용 DB(IssueTicket)가 아직 완전하지 않아 정확도가 제한적.

## 8. 일정/사용자/권한 (관리자 웹)

- [x] **긴급출동 일정** — 일정 유형에 "긴급출동"을 추가, 월 몇 회가 아니라 다음 날로 바로 잡히는
  방식으로 자동 생성.
- [x] **재점검 일정 타입** — 마찬가지로 일정 유형 선택지에 포함.
- [x] **호텔 담당자와 일정 공유** — 일정마다 고유 링크를 만들어서 호텔 쪽에 보내면, 로그인 없이도
  그 호텔의 방문 일정을 볼 수 있음(관리자 웹에서 "호텔과 공유" 버튼 클릭 → 링크 복사).
- [x] **요금 관리** — 서비스 유형별(정기점검/긴급출동/재점검/최초 리뉴얼) 기본 요금을 정하고,
  특정 호텔만 다른 요금을 쓰고 싶으면 별도로 지정 가능. 신규 "요금 관리" 메뉴에서 관리.
- [x] **호텔별 방문일정 관리, 담당자 배정, 정기점검 자동 생성, 미방문 알림** — 기존부터 구현돼 있던
  기능.
- [~] **현장점검자/호텔 담당자 권한 구분** — 화면상으로는 역할이 나뉘어 있지만, 실제 로그인/권한
  검사(누가 어떤 화면에 접근할 수 있는지 서버가 확인하는 것)는 아직 꺼져 있는 상태 — 이건 인증
  기능 전체가 임시 상태인 것과 같은 이유.

## 전체 요약

| 영역 | 완전 구현 | 부분 구현 | 미구현 |
| --- | --- | --- | --- |
| 점검 시작 | 5 | 1 | 1 |
| ROOM PRO | 9 | 3 | 0 |
| BATH PRO | 6 | 1 | 0 |
| 사진/영상 | 4 | 2 | 0 |
| 리포트/승인 | 6 | 2 | 1 |
| 관리이력 | 4 | 1(4개 항목 묶음) | 0 |
| 통계 | 8 | 2(각 여러 항목 묶음) | 0 |
| 일정/사용자/권한 | 5 | 1(2개 항목 묶음) | 0 |

**공통적으로 남아있는 미구현/부분 구현의 원인**은 대부분 두 가지로 좁혀진다.

1. **로그인/권한(AuthModule)이 아직 실제로 붙어있지 않음** — "담당자", "권한 구분" 관련 항목들이
   부분 구현으로 남은 공통 원인. 이건 이번 백로그 범위 밖의 별도 작업(Prisma/DB 연동과 함께 진행
   예정)이라 QA 체크리스트가 아니라 이 문서에서 원인을 명확히 짚어둔다.
2. **전체 점검점수, 유형별 통계 카드처럼 "기준/산식을 먼저 정해야 하는" 항목** — 코드로 바로 만들
   수 없고, 점수를 어떻게 매길지·어떤 유형을 몇 개까지 보여줄지 같은 제품 결정이 먼저 필요하다.

나머지(NFC 체크인, Quick-Draw 결과 저장, 확대사진 타입)는 클라우드 개발 환경의 한계
(실기기/개발 빌드 필요) 또는 이번 우선순위에서 의도적으로 후순위로 미뤄둔 항목이다.
