# 우선순위 B/C QA · 디자인 체크리스트

`docs/FEATURE_SCOPE.md` 4장의 우선순위 B/C 백로그를 구현한 뒤, "코드로 구현·검증까지 끝난 것"과
"사람이 실기기/실제 화면으로 직접 테스트하거나 디자인을 다듬어야 하는 것"을 구분해 정리한다.
`docs/QA_CHECKLIST.md`(Phase 7)와 같은 톤 — 후자를 미완료로 보는 게 아니라, 클라우드 개발 환경에서는
애초에 시각적 확인이 불가능한 종류의 작업이라는 뜻이다.

## 1. 모바일 — ROOM PRO 화면 (`RoomInspectionScreen.tsx`)

**구현/검증 완료**
- 객실 유형 칩, 청소 담당팀 칩(서버 `/cleaning-teams` 연동), 청소 완료 토글, 분실물 토글+보관 장소 입력
  블록을 담당자 의견 textarea 위에 추가. `npx tsc --noEmit` 클린, sync 시 서버에 정상 반영 확인(curl).
- 주의/긴급 항목에 문제 유형(곰팡이/누수/악취 등) 칩 행 추가.

**QA로 확인해야 하는 것**
- [ ] 실기기에서 새로 추가된 블록이 스크롤 흐름상 자연스러운 위치인지 (항목이 많아져 화면이 길어짐 —
  담당자 의견까지 도달하는 스크롤 피로도 체크)
- [ ] 청소 담당팀 목록이 서버 미기동/오프라인일 때 빈 배열로 조용히 처리되는지, 사용자에게 "팀 목록을
  불러올 수 없음" 안내가 필요한지 판단
- [ ] 분실물 보관 장소 입력 필드가 키보드 열렸을 때 다른 입력 필드를 가리지 않는지 (KeyboardAvoidingView 범위)

**디자인 다듬을 부분**
- [ ] 새로 추가된 4개 블록(객실유형/청소팀/청소완료/분실물)이 지금은 임시 칩 스타일로만 구현됨 —
  기존 화면의 카드/섹션 구분과 시각적 위계가 맞는지 디자이너 리뷰 필요
- [ ] 문제 유형 칩과 기존 상태(정상/주의/긴급) 칩이 색상 대비상 헷갈리지 않는지 확인

## 2. 모바일 — BATH PRO 화면 (`BathProInspectionScreen.tsx`)

  `media_kind: "VIDEO"` 태깅, 업로드 mimetype 분기 — 서버에서 `.mp4` 파일로 정상 저장 확인(curl).

**QA로 확인해야 하는 것 (실기기 필요)**
- [ ] iOS/Android 실기기에서 실제로 15초 동영상 녹화 → 저장 → 동기화까지 전체 플로우
- [ ] 동영상 파일 용량이 커서(수십 MB) 3G/LTE 환경에서 업로드가 오래 걸리거나 실패하는지, 업로드 중
  진행률/로딩 표시가 필요한지 판단 (현재는 사진과 동일한 업로드 큐 로직을 그대로 재사용해 별도
  진행률 UI 없음)
- [ ] 저사양 기기에서 동영상 촬영 시 메모리/버벅임
- [ ] "🎥 동영상" 버튼과 기존 "📷 사진" 버튼이 나란히 있을 때 오터치(잘못 눌림) 가능성

**디자인 다듬을 부분**
- [ ] 동영상 버튼 아이콘/라벨이 임시(🎥 이모지 + 텍스트) — 브랜드 아이콘 세트로 교체 필요
- [ ] 촬영된 동영상의 인라인 미리보기가 없음(사진은 썸네일 표시, 동영상은 표시 로직 미구현) —
  최소한 재생 아이콘이 얹힌 썸네일 정도는 모바일에도 추가할지 검토

## 3. 관리자 웹 — 대시보드 (`(dashboard)/page.tsx`)

**구현/검증 완료**
- "전월 대비 개선율" StatCard, "호텔별 문제 발생 순위"(랭크 배지), "담당자별 점검 실적" +
  "청소팀별 인스펙션 점수"(2열), "객실별 문제 발생 횟수" + "반복 문제 객실"(2열),
  "화장실 상태 변화 그래프"(신규 순수 SVG `StackedBarChart`, 정상/주의/긴급 14일 스택 막대)를 추가.
  `npx eslint src` / `npm run build` 클린, 실제 동기화 데이터로 curl 확인.

**QA로 확인해야 하는 것**
- [ ] 데이터가 아예 없는 신규 계정/호텔에서 각 섹션이 빈 상태를 어떻게 보여주는지 (현재는 배열이
  비면 섹션 자체가 안 보이거나 빈 리스트만 나올 수 있음 — "아직 데이터 없음" 문구가 일관되게 있는지)
- [ ] 데이터가 많아졌을 때(호텔 10곳 이상, 항목 수십 개) 리스트가 스크롤 없이 다 나열되는데 화면이
  과도하게 길어지지 않는지 — 페이지네이션/접기 UI 필요 여부 판단
- [ ] `improvementRatePercent`가 `null`일 때(데이터 부족) StatCard 표시가 "0%"처럼 오해되지 않는지 확인

**디자인 다듬을 부분**
- [ ] `StackedBarChart`는 완전히 새로 만든 순수 SVG 컴포넌트라 기존 `BarChart`/`DonutChart`와 톤앤매너
  (색상/여백/폰트 크기)가 정확히 일치하는지 나란히 놓고 비교 필요
- [ ] 섹션이 6~7개로 늘어나 대시보드가 상당히 길어짐 — 탭/아코디언으로 그룹핑할지, 아니면 지금처럼
  세로 스크롤 유지할지는 제품 결정 필요
- [ ] 랭크 배지(1위/2위…) 디자인이 임시 — 금/은/동 색상 같은 강조가 필요한지 검토

  복사 실패를 알아챌 수 있는지 — 현재는 catch에서 조용히 무시하고 있어 "복사됨" 피드백이 안 뜨는
  것 외에는 별다른 안내가 없음

**디자인 다듬을 부분**
- [ ] 일정 유형 뱃지 4종의 색상 구분이 명확한지 (긴급출동은 눈에 띄게, 정기점검은 차분하게 등)
- [ ] "복사됨" 텍스트 피드백이 버튼 라벨을 그대로 바꾸는 방식인데, 토스트/스낵바 형태가 더 적합할지 검토

## 6. 관리자 웹 — 요금 관리 (`rates/page.tsx`, 신규)

**구현/검증 완료**
- 전체 기본 요금 4종(정기점검/긴급출동/재점검/최초 리뉴얼) 시드, 호텔별 override 생성/수정,
  청소 담당팀 등록 폼까지 한 페이지에 구성. 사이드바/모바일 내비게이션에 "요금 관리" 진입점 추가.
  `npx eslint src` / `npm run build` 클린, curl로 CRUD 확인.

**QA로 확인해야 하는 것**
- [ ] 이 페이지는 이번에 완전히 새로 만든 화면이라 기존 페이지들과 달리 실사용 시나리오로 한 번도
  손으로 클릭해본 적이 없음 — 생성/수정/취소 흐름을 실제로 눌러보며 엣지 케이스(가격 0원, 음수,
  빈 문자열 메모 등) 확인 필요
- [ ] 같은 호텔+서비스 유형 조합으로 요금을 중복 생성하면 어떻게 되는지(현재 서버에 유니크 제약이나
  중복 방지 로직이 없어 보임 — 여러 개 생겼을 때 `resolve()`가 어떤 걸 쓰는지 확인 필요)
- [ ] 청소 담당팀 등록 폼이 이 페이지에 있는 게 직관적인지, 아니면 별도 메뉴가 나을지 (현재는 마땅한
  다른 위치가 없어 요금 관리 페이지 하단에 임시로 배치함)

**디자인 다듬을 부분**
- [ ] 이 페이지는 신규 화면이라 아직 디자이너 검수를 전혀 받지 않음 — 전체 레이아웃/여백/폰트가
  기존 `schedule`/`users` 페이지와 완전히 같은 패턴을 재사용했는지 나란히 비교 필요
- [ ] 요금 테이블의 "수정" 인라인 편집 UX(테이블 셀이 입력창으로 바뀌는 방식)가 다른 화면에 없던
  새로운 패턴 — 이 방식을 디자인 시스템에 편입할지, 모달 방식으로 바꿀지 결정 필요
- [ ] 사이드바 아이콘으로 "₩" 문자를 임시로 넣음 — 다른 메뉴들의 아이콘(◧ ◔ ◎ ▤)과 톤이 다르므로
  같은 스타일의 아이콘으로 교체 필요

## 7. 리포트/알림 (PDF·HTML, SMS)

**구현/검증 완료**
- 리포트 HTML/PDF에 객실 유형, 청소팀/완료시간, 분실물(강조 박스), 항목별 문제 유형 라벨 추가.
  URGENT 항목 발생 시 SMS(Mock)를 알림톡과 동시 발송, 알림 로그에 채널 구분 기록.

**QA로 확인해야 하는 것**
- [ ] 실제 PDF 파일을 열어(브라우저 미리보기 아님) 새로 추가된 블록들이 페이지 넘김 시 잘리지 않는지
  — 텍스트 줄 수가 많은 세션(문제 유형+분실물+청소 정보가 모두 있는 경우)에서 특히 확인 필요
- [ ] SMS는 현재 Mock이라 실제 문자가 발송되지 않음 — 실제 SMS 게이트웨이(알리고/네이버클라우드 등)
  연동 시 `sendSms()` 내부만 교체하면 되도록 설계했는지 코드 검토(연동 자체는 계정/API키 필요해
  이 세션에서 불가능)

**디자인 다듬을 부분**
- [ ] 분실물 강조 박스(🎒, 호박색)가 기존 리포트의 색상 팔레트(정상=초록/주의=호박/긴급=빨강)와
  겹치지 않는지 — 호박색을 이미 "주의" 상태에 쓰고 있어서 시각적으로 혼동될 수 있음
